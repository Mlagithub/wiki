
# Tidme 渐进学习：功能全景与架构分析（TiddlyWiki Server 版）

> 依据：`doc/research/import-stage-research-v2.md`（导入环节深研，v2 愿景）、`doc/supermemo/` 与
> `doc/supermemo_guru/`（SuperMemo 官方文档）、以及 Tidme 现状代码（`src/import`、`src/read`、`src/fsrs4tw`、`src/stats`）。
>
> **前提（用户明确）**：
> 1. 目标不止"切分器"，而是**在 TiddlyWiki 中实现类似 SuperMemo 的完整渐进式学习**，覆盖渐进学习领域主流软件的功能点；
> 2. 主要面向 **TiddlyWiki Server（TiddlyWeb）版本**——**无单文件容量风险**，二进制/大文本/全文检索/后台任务/多用户都可作为一等能力设计；
> 3. 已决策：twpub 全链路删除、导入统一到单一入口、切分器是通用工具（任意 markdown/HTML tiddler）。

---

## 0. 愿景与设计原则（一页）

**愿景**：TiddlyWiki Server 上的渐进学习系统——探索（导入/剪藏）→ 组织（切分）→ 阅读（渐进阅读）→ 制卡（摘录/挖空/问答）→ 复习（FSRS）→ 创造（概念网络/统计反哺）。算法用开源 FSRS，导入/切分/组织自研，deck 承担"牌组/概念"角色。

**设计原则**（源自 SuperMemo 哲学，`ux-optimization-plan.md` P1–P8）：
- **无压力**：导入不怕多、读不完不怕丢；优先级竞争代替焦虑；不给全有全无的选择。
- **漏斗**：导入量 >> 阅读量 >> 摘录量 >> 制卡量，漏斗应当可见。
- **一记忆一动作**：每张卡面前有明确轻量动作（Done/稍后/摘录/忽略），杜绝空转跳过。
- **最小信息**：挖空从单句 topic 生成，防 monster cloze；摘录卡允许长期粗糙，渐进精化。
- **键盘即专业**：Alt+X/Z、F7 三件套等快捷键是主路径。
- **块身份稳定**：SRS 状态附着在块上，ID 确定性派生，重导入/重切分不丢进度。

```
现状（插件结构）：
tidme/fsrs4tw  ← fork 自 TiddlyMemo：deck 引擎 + FSRS + 复习 UI（过滤器/状态机/按钮耦合其中）
tidme/read     ← 子模块：read deck + 阅读视图（twpub 已删，现为骨架）
tidme/import   ← 新写：pipeline（解析/切分/ID）+ widgets（导入/阅读闭环）
tidme/stats    ← sidebar 入口
```

**优点**：插件化利于按需安装；FSRS 是纯函数过滤器（双端可用）；字段驱动（卡 = 带字段的 tiddler）符合 TW 哲学；确定性 ID 方案已立。

**问题（重构理由）**：

1. **无统一 core**：数据模型约定散落（`emitTiddlers`、`buildExtract`、`buildCloze` 各写一份字段）；ID/FSRS/schema 没有共享服务层；新增实体（QA 卡、图片卡、复习日志）无处安放 → 三处会漂移。
2. **deck 引擎与 FSRS 耦合在 fsrs4tw**：fsrs4tw 是历史 fork（TiddlyMemo 血统），其 deck 状态机/过滤器与"渐进阅读"语义（按书 deck、topic/item 双轨、优先级）不匹配，且不能作为依赖被 read/import 引用（依赖方向倒置）。
3. **数据模型偏弱**：层级靠 `tidme.breadcrumb` 字符串 + `tidme.parent` 单链；无 Document/Section/Extract/Card 类型约束；重导入对齐、嵌套摘录、上下文回看都缺锚点字段。
4. **切分绑定导入**：切分器输入是文件字节，无法对任意 tiddler 执行（v2 愿景的核心），且无预览干预通道。
5. **无服务端利用**：解析全在浏览器（大 EPUB/PDF 客户端内存与带宽）；无后台任务、定时维护、二进制存储策略。
6. **刷新/状态一致性**：现有 TW 响应式列表在导入/评分后有时序问题（代码注释自述），需要统一事件/刷新策略。

### 4.2 数据模型设计（重构核心）

**实体与字段规范**（集中在 `tidme/core` 定义，TS interface + 运行时校验）：

```
Document（tidme-import-doc 标签）
  tidme.doc / tidme.source / tidme.author / tidme.language / tidme.url / tidme.date / tidme.license
  text（全文，server 版可完整存储）/ 章节索引

Section（阅读单元，tags [?][.]）
  tidme.doc / tidme.id / tidme.path（breadcrumb 展示用）/ tidme.order / tidme.level
  tidme.hash（内容指纹）/ tidme.kind=section / FSRS 族 / tidme.priority / tidme.parent=Document

Extract（摘录，kind=extract）
  tidme.parent=Section（或上级 Extract）/ tidme.kind / tidme.anchor（原文定位）/ 溯源继承（从 parent 链动态显示）

Card（问答/挖空，kind=qa|cloze）
  tidme.parent=Section/Extract / caption(正面) / text(背面) / cloze 宏 / FSRS 族

Deck
  card 选择器（结构化：path 前缀 + kind + 状态 + 优先级）而非纯标签
  每文档自动：$:/Deck/read/<书名>

ReviewLog
  $:/Deck/<deck>/log/YYYY0MMDD（已实现，扩展字段：rating/state/间隔/耗时）
```

**关键设计决策**：
- **parent 链是唯一权威层级**；breadcrumb 降级为展示派生值（由 parent 链重算），避免两处漂移。
- **ID 内容寻址**：docId=hash(源标题+指纹)；sectionId=hash(docId|path|ordinal)；extractId/cardId=hash(parentId|内容|序号)——重导入稳定（SRS 生死线）。
- **溯源动态继承**：extract/card 不复制 provenance 字段，经 parent 链 transclusion 动态显示（SM 引用注册表"改一处全局生效"的 TW 等价物）；`tidme.url/author` 等只需存在 Document。
- **优先级字段** `tidme.priority`（0–100）+ 状态字段（pending/outstanding/dismissed）入 schema，供队列排序。
- **原文锚点** `tidme.anchor`（Section 内片段定位：`#id` 或文本偏移），支撑高亮跳转/上下文回看（R3）。

### 4.3 模块划分（插件架构重构）

```
tidme/core（新增，其余插件依赖）
  ├── schema（实体/字段定义 + 校验）
  ├── ids（确定性 ID，双端）
  ├── fsrs（FSRS 服务封装：计算/参数/日志聚合）
  ├── deck-engine（deck 解析、队列选择、状态机、优先级排序）
  ├── events（tm-* 消息约定 + 刷新策略）
  └── server（服务端能力：后台任务、定时器、二进制存取）[server-only]

tidme/import  → core
  ├── 渠道（文件/粘贴/剪藏收件箱入口）
  ├── 解析器（epub/md/txt/html/pdf… 生产者：产出文档 tiddler）
  ├── 切分器（通用：任意 tiddler → Section 卡；预览干预）
  └── 导入中心 UI

tidme/read → core
  └── 阅读闭环 UI（导航/续读点/Done/高亮/摘录/挖空）+ 阅读视图

tidme/fsrs4tw → core（瘦身：复习 UI + deck 页 + 编辑工具栏；引擎逻辑上移 core）
tidme/stats → core（负载/保留率/漏斗面板）

依赖方向：import / read / fsrs4tw / stats → core（单向，无环）
```

**重构理由**：
- core 承载"学习语义"，消除三处字段漂移；deck 引擎从 fsrs4tw 上移，read/import 不再依赖复习 UI 插件；
- 保持插件边界（TW 用户可按需禁用 stats/read 等），但 core 是强制依赖；
- fsrs4tw 历史代码逐步替换而非推倒——先抽接口，再迁移 UI。

### 4.4 技术栈决策（Server 版）

| 能力 | 决策 | 理由 |
|---|---|---|
| **解析位置** | 轻量格式（MD/TXT/HTML）浏览器端即时解析；**EPUB/PDF 大文件走服务端任务**（上传 → Node 解析 → 落库 → 通知） | server 版无单文件限制；服务端无客户端内存/带宽压力；Node 端 jszip/DOMParser（或 xmldom）与浏览器同构 |
| **PDF** | 服务端 `pdfjs-dist`（Node）文本提取（tagged/线性）；复杂 PDF 文档化引导 marker/docling 自托管 | 避免 2MB+ 库进客户端；SM 先例：纯文本 + 链接 |
| **HTML 正文提取** | 浏览器端 Readability/Defuddle（剪藏已由 clipper 完成）；文件导入 .html 分支浏览器解析 | 无 CORS 问题（本地文件） |
| **二进制/图片** | **TiddlyWeb 二进制 tiddler**（图片/音频/PDF 原文），不内联 base64 进 wiki 文档 | server 版无单文件风险；图片卡（K6）直接可行 |
| **全文检索** | TiddlyWeb 内置搜索起步；量大时服务端索引（lunr 等） | 多设备/大库场景 server 版占优 |
| **定时任务** | 服务端 startup 注册定时器：每日 auto-sort/auto-postpone、逾期扫描、RSS 拉取 | SM auto-postpone 的 server 版实现（浏览器无法可靠做） |
| **后台队列** | 服务端简单任务队列（内存 + 持久化状态 tiddler）；进度写临时 tiddler 轮询 | 大导入不阻塞 UI |
| **LLM 辅助（远期）** | 服务端调用（密钥存服务端配置，不暴露客户端） | 语义切分/挖空建议/参数训练的安全前提 |
| **多用户（远期）** | TiddlyWeb bag 权限 + 每用户 deck 命名空间 | server 版原生能力 |

### 4.5 重构路线（分阶段，每阶段可交付）

| 阶段 | 内容 | 依赖 | 对应功能 |
|---|---|---|---|
| **A0 核心提取** | 新建 `tidme/core`：schema + ids + fsrs 服务 + deck-engine；把现有 fsrs4tw 的 FSRS 过滤器与 deck 状态机迁入 core（接口不变，UI 暂不迁移）；Document/Section 字段规范落地 | — | C1–C5 |
| **A1 切分泛化 + 统一入口** | 切分器输入改为"任意 tiddler text+type"（md/HTML/wikitext 分支）；`docId` 改源 tiddler 派生；导入中心（文件/粘贴/收件箱）；EPUB3 nav.xhtml；文档页生成 | A0 | I1–I4, S1–S5, D1 |
| **A2 阅读深度** | 阅读视图挂载（body.tid → section-bar + 排版）；高亮→摘录；上下文回看（锚点）；嵌套摘录 UI；进度聚合 | A0, A1 | R1–R6, K5 |
| **A3 调度体系** | 优先级字段 + 三档选择；auto-sort/auto-postpone（服务端定时器）；批量顺延/忽略/搁置；子集复习；topic/item 双轨完善 | A0 | F3–F6 |

**兼容策略**：A0 阶段保持现有 fsrs4tw UI 原样（仅引擎迁入 core，经 shim 引用），现有卡数据字段不变（schema 校验向后兼容缺省字段）；A1 之后旧格式 Section（无 `tidme.parent`）可经一次性清洗脚本补链。

### 4.6 风险与开放问题

- **fsrs4tw fork 历史包袱**：其 deck 状态机/过滤器的"学习语义"与 core 设计可能冲突——重构时先以接口隔离，逐功能迁移，避免大爆炸。
- **parent 链迁移**：现有数据 `tidme.breadcrumb` 为主、无 parent 链——需迁移脚本（breadcrumb 反推 parent）与校验兜底。
- **服务端解析的进程模型**：TiddlyWeb 插件跑在 Node 进程内，长时间解析会阻塞 wiki 服务——后台任务需异步（setImmediate/worker）或独立进程。
- **多用户与数据隔离**：TiddlyWeb 多用户需明确"每用户 deck/进度"归属（字段级 vs bag 级），影响 core 的 schema。
- **定时任务可靠性**：服务端重启后任务恢复；时区/用户本地日界 vs 服务端日界（auto-postpone 按谁的一天？）。
- **文档大文本**：server 版可存全文，但 Section 卡仍应只存节文本（保持队列加载快）；全文检索走 Document 或索引。
